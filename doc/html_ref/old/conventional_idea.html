Some of conventional MCUs common use, specific for MAX301xx project

For HR and SpO₂ projects with MAX3010xx sensors, low-power MCUs like TI MSP430 or Silicon Labs C8051 handle basic algorithms (peak detection, moving average, ratio-of-ratios) efficiently. Specialized MCUs like Holtek BH66F2560/HT32F59045 integrate the analog front-end, simplifying design, while 32-bit MCUs (STM32, nRF52) support more advanced filtering and adaptive algorithms, balancing power, processing, and sensor integration.

ATmega328P Datasheet

The ATmega328P The ATmega328P is quite efficient for typical control and embedded tasks with an 8-bit ALU and a hardware multiplier, but it is not optimized for heavy number-crunching (large integer arithmetic, floating point, DSP style operations). Common boards that use the ATmega328P microcontroller include the Arduino Uno, Arduino Nano, and Arduino Pro Mini.

Algorithm and codes library to working with MAX3010xx series

SparkFun MAX30105

The SparkFun MAX30105 Arduino library reads raw red and IR signals from the sensor, applies a simple moving average to reduce noise, removes the DC baseline to isolate the AC component, and calculates heart rate via threshold-based peak detection. SpO₂ is estimated using the ratio-of-ratios method with floating-point arithmetic. The library relies on basic integer multiplication/division and simple smoothing, with no advanced filters, motion artifact handling, or user calibration, making it suitable for basic Arduino projects but limited in accuracy for more demanding or wearable applications.

    • Arduino-MAX30102 by thewiseguyshivam

    The Arduino-MAX30102 repo implements basic HR and SpO₂ measurement from MAX30102 sensors using software-based processing without advanced DSP. Raw red and IR signals are smoothed with simple moving averages, and heart rate is calculated via threshold-based peak detection, while SpO₂ is estimated using the ratio-of-ratios method with floating-point arithmetic. Multiplication and division are used for averages and ratio calculations, with floats handled in software on 8-bit MCUs and hardware-accelerated on 32-bit MCUs. There are no FIR/IIR filters, adaptive algorithms, motion artifact handling, or FFT-based processing, making the library lightweight and suitable for low-power MCUs but limited in accuracy and robustness for wearable or high-performance applications.

    • Arduino C code for MAX30102 pulse oximetry sensor

    The MAX30102_by_RF library implements an enhanced signal-processing algorithm for the MAX30102 pulse oximeter, replacing the standard Maxim reference code with a more precise floating-point implementation. It incorporates autocorrelation and Pearson correlation coefficients to assess waveform quality, ensuring reliable heart-rate and SpO₂ estimation only from valid PPG segments. The algorithm includes improved moving-average filtering and refined peak detection logic for better temporal resolution. However, it lacks adaptive or motion-compensated filtering, relying instead on signal-quality metrics to reject corrupted data. Designed for mid-range MCUs with sufficient memory, the library provides a technically robust framework for stationary or low-motion PPG measurement applications.

    • DFRobot_MAX30102 Heart-rate & Oximeter Sensor Library

    The DFRobot_MAX30102 library provides basic functions to configure and read data from the MAX30102 heart-rate and SpO₂ sensor, including adjustable LED brightness, sampling rate, averaging, and data acquisition for red and IR signals. It includes a built-in method to estimate heart rate and oxygen saturation but does not document the underlying algorithms or filtering methods in detail. The only clear filtering is sample averaging, with no mention of digital filters or motion artefact removal. The SpO₂ and heart-rate computations appear to use a simplified or proprietary approach without calibration or adaptive filtering.
